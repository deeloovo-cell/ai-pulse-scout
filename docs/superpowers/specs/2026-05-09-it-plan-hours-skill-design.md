# IT人员计划工时查询 Skill 设计文档

- 日期：2026-05-09
- 名称：IT人员计划工时查询
- 类型：混合型业务分析 Skill（默认 IT 工时表口径，可覆盖参数）
- 默认输出模式：个人明细型

## 1. 目标

将反复出现的 IT 人员计划工时查询需求沉淀为一个可复用 Skill，支持从 Excel 明细表中读取任务数据，按开始/结束日期将计划工时分摊到工作日，识别未来两周或指定日期范围内单日计划工时低于阈值的人员，并输出前十验证结果或完整 Excel 导出结果。

Skill 应优先服务当前高频场景：
- 基于 Excel 文件输入
- 默认按个人输出异常明细
- 明确列出异常日期
- 支持排除离职人员
- 支持导出完整 Excel

同时保留通用性，允许覆盖列位、阈值、日期范围、排序方式和输出粒度。

## 2. 典型使用场景

### 场景 A：个人异常明细
用户发送 IT 工时明细表，要求查询未来两周内单日计划工时低于 0.5 的人员，明确到哪些工作日，并先输出前十条核对。

### 场景 B：导出完整名单
在确认前十结果准确后，用户要求按相同格式导出完整 Excel。

### 场景 C：排除离职人员后重算
用户要求在原口径不变的前提下排除已离职人员，并重新输出 Excel。

### 场景 D：口径覆盖
用户指定不同列位、不同阈值、不同日期范围，或要求切换为岗位汇总视图。

## 3. 核心设计

### 3.1 输入模式
采用混合型设计：

1. **默认模式**
   - 面向当前 IT 工时明细表场景
   - 默认识别常见列：姓名、岗位、开始日期、结束日期、计划工时
   - 默认输出个人明细

2. **覆盖模式**
   - 用户可显式指定：
     - 姓名列
     - 岗位列
     - 开始日期列
     - 结束日期列
     - 计划工时列
     - 阈值
     - 日期范围
     - 是否排除离职
     - 排序方式
     - 输出粒度（个人/岗位）

### 3.2 默认口径

默认按以下规则计算：
- 输入：Excel 文件（优先 `.xlsx`）
- 输出粒度：个人明细
- 查询范围：未来两周工作日
- 分摊方式：将单条任务的计划工时在开始日期到结束日期之间的**工作日**平均分摊
- 异常判定：单日计划工时 `< 阈值`，默认阈值为 `0.5`
- 离职过滤：默认可选，若用户提出则排除姓名中含“离职”的人员
- 排序：默认按异常工作日数降序；若并列，再按这些异常日期工时合计升序，再按姓名升序

### 3.3 输出模式

#### 模式 1：前十验证
适用于用户先看样例确认口径。

默认字段：
- 排名
- 姓名
- 岗位
- 低于阈值的工作日数
- 这些日期工时合计
- 具体日期（如 `2026-05-11（0.00）；2026-05-12（0.00）`）

#### 模式 2：完整明细
输出全部命中人员，字段与前十验证一致。

#### 模式 3：Excel 导出
生成 Excel 文件，至少包含：
- 姓名
- 岗位
- 低于阈值的工作日数
- 这些日期工时合计
- 具体日期
- 日期范围内每个工作日对应工时列（便于复核）

#### 模式 4：汇总视图（可选）
仅在用户明确要求时启用，例如：
- 按岗位分类
- 按人数汇总
- 按异常日期数汇总

## 4. 组件设计

### 4.1 Skill 文档层（SKILL.md）
负责：
- 定义触发条件
- 说明适用场景
- 规定默认计算口径
- 规定用户澄清顺序
- 规定输出格式优先级
- 规定导出结果的处理方式

### 4.2 脚本层
建议提供本地脚本（如 Python），负责：
- 读取 xlsx 文件
- 解析 sheet 与列位
- 将计划工时按工作日分摊
- 在“人-日期”粒度汇总
- 过滤低于阈值的记录
- 过滤离职人员
- 生成终端预览结果
- 导出 Excel

### 4.3 配置层
可选提供默认配置文件或脚本内默认常量，至少包括：
- 默认阈值：0.5
- 默认日期范围：未来两周工作日
- 默认过滤规则：姓名包含“离职”时视为离职候选
- 默认排序规则：异常天数降序

## 5. 数据处理规则

### 5.1 日期处理
- 优先支持 `YYYY-MM-DD`
- 兼容 Excel 日期序列值
- 若开始/结束日期缺失，则该条任务默认不参与逐日分摊

### 5.2 工时处理
- 计划工时列应可解析为数值
- 非数值或缺失值默认跳过该条任务
- 若开始到结束之间无工作日，则跳过该条任务

### 5.3 工作日定义
当前版本默认按周一到周五作为工作日；法定节假日与调休日暂不内建，后续可扩展。

### 5.4 离职识别
默认规则：姓名中包含“离职”视为离职人员。后续可扩展为：
- 使用状态列
- 使用单独人员台账
- 使用更细粒度正则规则

## 6. 交互规则

### 6.1 信息充足时
如果文件已给出，且默认列位能够识别，则直接计算并返回结果，不额外追问。

### 6.2 信息不足时
按以下顺序补充澄清：
1. 用哪一张表/哪个 sheet
2. 姓名列、岗位列、开始列、结束列、计划工时列分别是哪一列
3. 日期范围是未来两周还是指定区间
4. 阈值是多少
5. 是否排除离职人员
6. 输出前十、完整文本、还是导出 Excel

### 6.3 输出优先级
默认优先级：
1. 个人明细
2. 明确异常日期
3. 前十验证
4. 完整导出
5. 汇总视图（仅用户明确要求时）

## 7. 错误处理

Skill 需要明确处理以下情况：
- 找不到 Excel 文件
- 表头与预期不一致
- 用户给的列位为空或列中无数据
- 开始/结束日期无法解析
- 计划工时列不是数值
- 导出成功但发送失败

响应原则：
- 先说明发现的问题
- 再给出最小必要的澄清问题或替代方案
- 不要在用户要求个人明细时擅自改成岗位汇总

## 8. 成功标准

一个成功的 Skill 应满足：
- 面对相同类型 Excel 可稳定复用
- 默认输出贴合当前 IT 工时排查需求
- 前十验证结果与导出结果口径一致
- 支持一键排除离职后重算
- 支持后续扩展为更通用的 Excel 工时分析

## 10. 后续实现范围

本次实现建议包含：
- `SKILL.md`
- 一个可直接执行的本地脚本
- 至少覆盖以下能力：
  - 读取 `.xlsx`
  - 工作日分摊
  - 个人明细输出
  - 前十预览
  - Excel 导出
  - 排除离职

暂不包含：
- 节假日配置
- 多文件合并分析
- 自动识别所有复杂变体表头
- 图表化展示

## 11. 推荐实现决策

推荐采用“Skill 文档 + 本地脚本”的方案，而不是纯文档方案。原因：
- 需求会重复发生
- 结果要求高度结构化
- 导出 Excel 是高频动作
- 同一口径下多轮重算需求明显
- 单靠 `SKILL.md` 容易造成步骤冗长且不可复用

因此，后续实施时应优先把计算逻辑沉淀到脚本中，让 Skill 负责选择口径、驱动脚本、整理输出、发送文件。
